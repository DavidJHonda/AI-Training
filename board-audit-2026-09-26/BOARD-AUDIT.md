## Preventing recurrence

Generate an asset-level register from `index.html` at build time (path, lesson, format/exception, native size, intended CSS cap, renderer/source, cache key). For each new or revised board, render from an editable source, reject essential type below its format floor, and review an automated **880 px same-width sheet next to lesson peers** plus the native image before publishing. Keep source-to-delivered image identity explicit so old renderers cannot silently replace newer raster edits. A small screenshot check of the actual lesson layout should accompany any CSS width change.

## Audit limits

This audit evaluates current page-referenced raster assets and static sizing/caching rules. It does not audit video frames, print packets, unused image alternatives, or live network cache state. The close images switch to live HTML at narrow widths; their raster typography conclusions therefore apply to the desktop image path. The `BOARD-INVENTORY.md` does not resolve every hybrid five-card layout to a named format, so those cases are identified rather than forced into `EE-FLOW` or `EE-3FB`.
