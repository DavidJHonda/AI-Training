# Be Smarter Than the Tool — Project Briefing

## What this is
An instructor-led AI education web app for high schoolers, built to be taught live but easily repurposed for self-paced use. Single HTML file (index.html) with inline React. Deployed via Vercel from GitHub repo "AI-Training". Owner: David. Audience: his twins and other 16-year-old students.

### Structure conventions (house patterns)
- **Git is the archive, not dead runtime code.** `SECTION_GROUPS` is the source of truth for what is routed. Every routed id must resolve in `SECTION_META` and `SECTION_COMPONENTS`; an extra component, registry entry, or metadata entry is legacy drift to verify and remove, not material to preserve deliberately. Use Git history for recovery and `docs/parking-lot.html` only for intentionally retained copy or ideas.
- **ids are stable across retitles.** A lesson keeps its internal id when its label or kicker changes (e.g. `modelselection` is now "Which App?", `aihistory` is "How an LLM Works", `attention` is "Transformer"). Don't infer a lesson's content from its id.
- **Merges use the `embedded` prop.** A merged-in lesson's component gains an `embedded` prop that swaps its `LessonHeader` for a `SectionKicker` seam, then renders inside the surviving lesson; the surviving lesson drops its own closing `LessonRule`/`NextLessonGate` in favor of the embedded component's, which becomes the merged lesson's one closing gate. Example: `PrivacySection` (`embedded: true`) renders inside `IntegritySection` for Habits for the Road, with `PrivacySection`'s own trailing gate carrying the course-ending "Back to Start" button. PrivacySection is currently the only component rendered in embedded mode.
- **Kickers can be vestigial.** A `SECTION_META` kicker is not always rendered; the lesson eyebrow shows the GROUP label. Changing a kicker often has no visible effect.
- **Cut-but-reusable copy** goes in `docs/parking-lot.html`, not commented out in index.html. It's a styled static page (was `parking-lot.md` until 2026-08-15); add new entries as plain semantic HTML at the top of its `<main>` — the entry template lives in a comment there, and the page's table of contents builds itself from the `<h2>` tags.
- **Delete verified dead code.** Before removing a component, data set, style, or branch, check its definition, registries, and call sites. Once it is confirmed unreferenced, delete it; Git keeps the recoverable history. Unreachable paths inside live components are especially risky because their props sit beside working ones and can look supported when they are not.

## Design system

### Tokens (CSS custom properties, defined in :root)
- Colors (surfaces): --bg #f6f5fb, --card #fff, --primary #6e51ff, --primaryDeep #4c2dff, --primaryFaint #f7f4ff
- Colors (text): --ink #0e0a1f, --inkSoft #3a3550, --inkMuted #6e6986, --inkFaint #b3aec8
- Colors (lines): --rule #e7e3f2
- Colors (semantic): --green #1f9d5f, --red #d4334a, --info #3b82f6, --info-bg #eff6ff
- Sand/amber presentation colors: legacy token names --seeBand #faf6ec, --seeAccent #a36a17, and --seeRule rgba(163, 106, 23, 0.35). Live static content still uses these values, but SEE IT is no longer a course activity type.
- TRY IT band: --tryBand #eef4eb (mint activity surface), --tryRule rgba(63, 107, 63, 0.18) (mint hairline divider), --tryAccent #2f7d4f (green accent; mint InteractiveBox eyebrows and TRY IT Takeaway completions). The AIBubble reuses the same mint as its fill, documented under UserBubble/AIBubble.
- ILLUSTRATION band: --illoBand #f5e1d4 (warm sand surface), --illoAccent #b5532f (terracotta accent). Opener-support display band; see Illustration component.
- Typography: --sans (Plus Jakarta Sans, Google Fonts) for all reading text, --serif (Instrument Serif, Google Fonts) for display moments only (lesson titles, activity numerals, and opener/Illustration display phrases), never explanatory prose or feedback. --mono (system monospace stack). Source Serif 4 is no longer used; it was retired when all explanatory and feedback prose moved to sans.
- Shadows: --shadowSoft (0 4px 12px rgba(14, 10, 31, 0.05)) for inner cards, pills, and counters; --shadowElevated (0 8px 22px rgba(14, 10, 31, 0.05)) for support cards. Active-glow and a few one-off elevated/inset shadows remain inlined per-use, mostly on assessment and diagram surfaces.
- Body paragraph standard: 17px / 1.65 line-height / var(--inkSoft)

### Design philosophy
- Borders are rare in page-level chrome and narrative containers. ShowcaseBox, CompareCard, and InteractiveBox surfaces use fill + shadow with no border.
- Activity interiors may use --rule borders where the border carries meaning, separating choices, feedback, and interactive states.
- Two shadow tokens: --shadowSoft (inner cards, pills, counters) and --shadowElevated (support cards). Active-glow and one-off elevated/inset shadows are inlined per-use on assessment and diagram surfaces.
- Active states are singular: one section pill, one chip, one primary action per page.
- Serif (Instrument Serif) is for display moments only: lesson titles, activity numerals, and editorial display phrases inside opener Illustrations and late synthesis headings. Every other piece of text, including all explanatory prose and activity feedback, is sans (Plus Jakarta Sans). The old reading serif (Source Serif 4) has been retired. Two additional fonts exist solely for the welcome/name-gate screen, which implements the "Course Opener" design from the claude.ai/design project (2026-07-14): Caveat for the "Luke and Nate" handwritten signature, and Playfair Display italic for the title's "Than the Tool" line. Both are applied via gate-* CSS classes in the head style block; do not use either elsewhere.
- Draft lessons: `isDraftLesson` uses `faketrap` as the boundary. Lessons after it render in red with "<Title> · Draft", except the first lesson of each group, which is never marked draft. In the current spine, Avoid Traps and all earlier groups are final; the Embrace the Future and Finish Smarter openers are the non-draft exceptions after the boundary. Since the 2026-08-15 Finish Smarter merge (phases 1–2 complete), every Finish Smarter lesson after the opener shows as draft-styled — Tune the Model, Creative Thinking, Be Curious, What You Learned, and the merged Habits for the Road — an accepted side effect until the section's four planned new lessons (AI Tips, Communication & People, a rebuilt Skills That Matter, Make Your Move) are built and lessons graduate individually. Move the boundary id as lessons graduate.
- Page background never goes white.
- Vertical rhythm: card-level blocks (InteractiveBox, ShowcaseBox) carry a default bottom margin of var(--blockGap) (24px); body paragraphs use 18px. Blocks render in normal flow, so adjacent margins collapse to the larger value and never stack. Pass marginBottom/marginTop to override. Spacing inside components and diagrams is still inline per-context; there is no global numeric scale beyond --blockGap.

### Components (defined near top of file)
- **BodyP**: standard body paragraph (17px / 1.65 / var(--inkSoft)). Props: marginBottom (default 18), style (additional overrides like maxWidth). Used for all lesson prose. Inline `<p>` is reserved for non-standard sizes (captions, card body text).
- **LessonHeader**: section-name eyebrow + serif title + optional subtitle. Eyebrow is a short rule line plus the section group name, uppercase, in var(--inkMuted) — no "SECTION NN" / "LESSON NN" numbers (position is already shown by the nav and sticky bar).
- **SectionKicker**: page-level (size="large", 18px) or pre-content (size="small", 13px). Both purple, uppercase, weight 700. Also serves as the in-body section break within a lesson — what used to be LessonSubhead is now a SectionKicker call. Default behavior is no kicker. **When to add one:** a SectionKicker signals a *new thought or topic turn*. Add it when the element it precedes introduces an idea the reader isn't already set up for; omit it when the copy directly above already establishes the subject (a kicker there just repeats what's been said). Quick test before any block (paragraph, ShowcaseBox, etc.): does the sentence right above already tell the reader what this is about? If yes → no kicker; if it turns to something new → add one. Examples on Why Learn AI?: the White House PullQuote has *no* kicker — the line right above it ("Here's how it describes what AI makes possible:") already sets it up, so the quote only delivers on it; "AND IT CUTS BOTH WAYS" *has* one because it pivots to a new idea (the flip side: AI quietly working against you). Activity kickers (the TRY IT / LAB NN lead rendered by ActivityLead, and the AI Multiplier's self-rendered aim-eyebrow) carry a leading 24×2px accent dash before the label (per David 2026-07-14); plain topic-turn kickers do not get the dash.
- **ShowcaseBox**: framed callout for introducing or illustrating a concept, typically containing supporting cards. --primaryFaint fill, no border, borderRadius 20, padding 24. Props: kicker, headline, intro, marginBottom (default 24px), children.
- **InteractiveBox**: activity container. `variant` recognizes `"lab"` (⚒ LAB, optionally numbered); every other value renders as `"try"` (✎ TRY IT). `surface` separately controls mint, sand, teal, or the default dashed-purple chrome. Optional `lead` renders an `ActivityLead` before the box and suppresses the duplicate internal eyebrow; other props include title, hint, action, marginTop, marginBottom, and children. There is no implemented `"see"` variant even though older documentation and screenshots used that name.
- **InnerCard**: standard white inner card used inside activities. White fill, 14px radius, --shadowSoft, default padding 22px 26px. Pass `pad="snug"` for the compact 18px 22px layout. Accepts a style prop for other overrides (display flex, marginBottom, custom padding) and children. Use instead of hand-building white cards inside InteractiveBox or RevealSequence.
- **ActivityCounter**: the "X of N" progress pill for an activity's `InteractiveBox.action` slot. White pill, 999 radius, --shadowSoft, bold count plus uppercase "of N". Props: count, total. Current live call sites are checkbox LABs, where it reports checked steps; live TRY ITs do not use it.
- **ActivityButton**: dark-ink fill, white text. Used inside activities for in-activity actions. Sizes: default and "large". (`RevealSequence` currently hand-builds visually matching buttons rather than calling ActivityButton; a future cleanup may consolidate them.)
- **NextLessonGate**: bottom-of-lesson card navigation. It renders a PreviousCard plus an always-unlocked NextCardUnlocked. Clicking the next card marks the current lesson complete and navigates; activities do not gate advancement. `NextLessonGate` does not currently read `ready` or `lockedMessage`. Restoring gated advancement would be a product and interaction change.
- **OpenerSection**: standardized opener-page wrapper. Slots: LessonHeader (with optional bigIdea subtitle), whyThisMatters paragraphs (a `{ kicker: "..." }` entry in that array breaks the run with a SectionKicker), optional featuredCard, the required `sectionOverview` "IN THIS SECTION" box built from `groups` (each group has a kicker label, a bridge subhead, and its own card grid), optional "The common mistake" kicker + paragraph, framing "Keep this question in mind" kicker + paragraph (rendered from each opener's `question` prop), and the standard "Mark as complete" NextLessonGate (was a nav-style gate until 2026-07-14). Each section group's opener is a thin wrapper passing content props, so format changes propagate to every opener. The alternative no-overview branch (a "BIG QUESTIONS WE'LL ANSWER" kicker, `whatYoullLearnIntro`/`whatYoullLearnClosing` paragraphs, a flat `openQuestions` card grid) was deleted 2026-08-10: every opener sets `sectionOverview`, so it never ran and its copy never reached the page. Copy is parked in `docs/parking-lot.html`.
- **Illustration**: display band used by Welcome, the five live OpenerSection wrappers, and What You Learned. Tinted band (--illoBand fill, no border, 20px radius, 24px 28px padding) with an uppercase --illoAccent eyebrow (default "◆ ILLUSTRATION"), optional headline and intro, and a children slot. The children slot holds the large Instrument Serif display phrases (clamp ~28-40px); this is the documented exception to the serif rule.
- **QuizBlock**: recessed --bg fill, --rule border. Statement is sans 22px/600/--ink. Per-option correctness via opt.correct.
- **RevealSequence**: a props-driven progressive-disclosure renderer. Its caller owns `started`, `currentIdx`, completion, and advance state; the component renders the start/next/finish controls and either the supplied children or `completionElement`. It does not manage stage state itself. The only current call site is Privacy's fully revealed "The Whole Photo" display, so the richer progressive patterns described in older notes are not live-course conventions.
- **Takeaway**: optional activity conclusion. Two-column grid (1fr / 2fr, 36px gap): left is an uppercase 11px eyebrow (default "The takeaway") above a 24px/600 sans headline; right is the 16px sans explanation. Props: headline, body, eyebrow, accent, merged. Standalone mode renders a white card; `merged` renders only a dashed top divider plus the grid, although no current call site passes `merged`. Same var(--primaryFaint) band geometry as CompareBox (22px radius, 32px 40px padding, optional 20px/800 `headline`), holding a split-tint inner panel (24px radius, hard 50/50 linear-gradient between the two column bgs) with two column headers (CompareHead-style type; left column left-aligned, right column right-aligned) above one white rows card (16px radius, var(--shadowElevated)). Props: index (1-based), kicker, prompt, answered, correct, feedback, headline, eyebrow, children. headline and eyebrow override the feedback strip defaults; several sorts pass them per item.
- **FeedbackPill**: pill button for parallel sort activities. Driven by booleans `answered`, `isCorrect`, `isPicked` (plus `label`, `onClick`); a legacy precomputed `state` string is still accepted but no longer passed by any activity. Four looks: neutral white, green for a correct pick, solid red for the current wrong pick, and pale red for a remembered earlier wrong pick. Green only appears on a pill the student actually picked; the correct answer is not auto-revealed.

### Activity Patterns
The live course uses these patterns:

- **TRY IT shell:** `InteractiveBox` with `variant: "try"` (or omitted) and usually `surface: "mint"`. A `lead` may render the purpose-and-task paragraph before the box through `ActivityLead`; title and hint remain optional.
- **Parallel row activities:** many live TRY ITs show all prompts at once using `ScenarioRow` plus `FeedbackPill`, or use repeated `QuizBlock` instances. Each activity owns its state and completion callback. Current examples include "How did AI learn to do this?" (`trainingbias`) and "Match the Task to the Effort" (`choosemodel`).
- **Bespoke activities:** games, text entry, builders, redaction, sliders, and other custom interactions are common and should be verified at their actual call sites rather than forced into a generic taxonomy.
- **LAB shell:** `InteractiveBox` with `variant: "lab"` and `surface: "teal"`. Checkbox labs commonly use `LabStepList` and `ActivityCounter`, although several older labs still inline their rows.
- **Static demonstrations:** explanatory page content uses `ShowcaseBox` or lesson-specific markup. `RevealSequence` has one live, already-complete call in Privacy's "The Whole Photo" display.
- **Takeaway:** optional. Live activities may render it after custom interactions; it is not required for either parallel or progressive activities.
- **Advancement:** activity callbacks can record completion state, but `NextLessonGate` is always unlocked and ignores `ready` and `lockedMessage`. Do not document activity completion as a navigation gate unless the implementation changes.

When adding or changing an activity, copy a current live lesson with the same interaction shape and confirm the shared component implementation in `index.html`. Do not use dated component screenshots as behavioral specifications.

## Lesson structure

### End-of-lesson transitions
A lesson ends on its landing beat (a closing kicker and its paragraph, a Takeaway, or a completed activity). It does not end on a forward-pointing paragraph. The NextLessonGate button is the structural pivot; a "...next lesson, we'll..." sentence dilutes the insight and adds reading load.

If a transition is genuinely needed for orientation, it goes at the top of the next lesson, not at the bottom of the current one. Each lesson reads as a standalone unit; the next lesson sets up its own question.

Practical rules:
- The last component before LessonRule should be a closing kicker and its paragraph, a Takeaway, or an activity-completion beat. Not a BodyP that pivots forward.
- The KeyInsight band (🔑) was retired 2026-08-10. Its landing beats became a SectionKicker carrying the point plus a BodyP carrying the body. Do not reintroduce it.
- Closing paragraphs should not trail off with "...next we'll..." or "...that's the idea behind X." Trim those sentences.
- Forward references inside mid-lesson copy are fine. The rule applies to the lesson's final beat.

### Illustrations
